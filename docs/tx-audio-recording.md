# TX audio recording

Select USB, LSB, AM, FM or generic SSB to match the client, click **Record WAV…**, choose a file,
transmit, then click **Stop**. Output is PCM WAV, 48 kHz, 16-bit, mono.
Only transmit periods are recorded; pauses between transmissions are omitted.
Closing the emulator or switching profiles also finalizes the WAV header.
After each successfully completed manual or automatic recording, File Explorer
opens with the saved WAV selected. The file is closed before Explorer opens;
repeated Stop commands do not open additional windows.

Input is TX IQ, not speaker audio. SSB uses the real baseband component;
AM uses envelope detection and DC removal; FM uses a phase discriminator
assuming 5 kHz deviation. The protocol does not transmit the modulation mode.
Digital modes, CW and frequency-offset TX IQ are not general-purpose speech decoding.

## No speech / no TX spectrum in Thetis

The emulator sends silent hardware microphone samples. It does not currently
capture a local PC microphone. Thetis must obtain speech through its own VAC1
input (select the PC microphone and ensure VAC bypass is off), or another
client-side audio source. Selecting the radio microphone supplies silence here.

The TX input diagnostic works independently of recording and distinguishes:
PTT off, PTT on with no IQ packets, received all-zero IQ, and nonzero IQ with a
measured sample peak in dBFS. This identifies whether audio was generated by the
client before attempting playback or RF-feedback troubleshooting.
The P2 control diagnostic also shows the last accepted control flags/sequence,
receive/processing ages, queue delay and HP/TX queue lengths. RUN+PTT is 0x03
(possibly with additional bits); RUN without PTT is 0x01. Normal client traffic
refreshes the client activity indication; P2 control packets need not be periodic.

P2 input queues and output catch-up are bounded per loop. High-priority control
is serviced between TX-IQ batches and during RX catch-up. Receive callbacks
enqueue before rearming to preserve socket ordering. Older nonzero control
sequence numbers from the same peer are rejected; zero can restart sequencing.
This prevents a busy TX stream from delaying PTT until release. Regression tests
cover a 4096-packet TX backlog and auto recording through PTT-on/off, and actual
UDP PTT edges with continued IQ/microphone output. Live Thetis behavior still
requires confirmation with this revision.
By default receiver IQ is muted while transmitting. Unchecking **Mute RX during
TX** restores P2 test signals / P1 legacy loopback. The emulator does not emulate
a full RF feedback/PureSignal path. Muting receiver IQ does not generate TX speech.

### Protocol 2 microphone clock correction

Thetis `network.c::ReadUDPFrame` requires 132-byte microphone packets from
source port 1026: a 4-byte sequence plus 64 PCM16 samples. Its TX processing
consumes 64 samples per packet even when VAC supplies the actual audio.
The inherited emulator sent 1444-byte/720-sample packets at approximately
66 packets/s instead of the required 750 packets/s. That violated Thetis'
packet-length check and did not supply the expected TX processing cadence.

The emulator now sends 132-byte packets at 750 packets/s, using monotonic
elapsed time and cumulative sample accounting. Samples remain silent on the
hardware-microphone input; VAC speech is still supplied by Thetis. Automated
tests verify packet length, sequence, silence, 48 kS/s pacing over 60 seconds,
and the production sender through a local UDP receiver. Live VAC speech
behavior with this correction still needs verification. Protocol 1 is unchanged.

P1 uses 16-bit IQ at 48 kS/s. P2 uses 24-bit IQ at integer multiples of 48 kS/s
up to 1536 kS/s. Downsampling averages samples and expects client-band-limited
speech. FM de-emphasis is not applied. UDP loss is not reconstructed.

Disk writes use a bounded background queue; buffer overruns are reported in
the status. Maximum WAV size is approximately 4 GB. A clean stop finalizes the
file; a process crash can leave it unfinished. This is an audio monitor, not a
calibrated or archival IQ recording.

## Automatic recording

**Auto record TX: OFF** is the default on startup and after selecting another
radio profile. Choose the transmit mode first, click the button and select a
destination folder. The button changes to **Auto record TX: ON**.

Each PTT rise starts a new WAV file; PTT release finalizes it. Repeated PTT
control packets do not create extra files. Enabling while already keyed records
the remainder of that transmission. Clicking the button again disarms recording
and finalizes the current file. Closing the emulator or switching profiles also
flushes and closes pending recordings. Manual recording and automatic recording
are mutually exclusive in the UI.

Names include the local recording date/time (milliseconds) and selected mode,
for example `TX_2026-10-28_14-35-12-084_USB.wav`. Collisions receive a unique
suffix rather than overwriting an existing file. The client does not transmit
USB/LSB/mode metadata: the filename uses the manually selected mode, fixed while
auto recording is armed. Change it by disarming and rearming.

PTT transitions and IQ blocks are queued in order for a background worker;
file creation and header finalization do not run on the UDP thread. An input
queue overrun disables automatic recording and reports an error. A missing
PTT-release packet cannot be inferred reliably; disarm manually if the client
disconnects without sending its stop state.

Tests cover synthetic 1 kHz SSB/AM/FM, WAV headers, duration, DC rejection,
PTT gating, restart and the actual P1/P2 TX-IQ handlers. Live microphone
recording still needs user verification.
